# Testing & Regression Prevention

코드 수정 후 다음 워크플로우를 따른다.

## Browser Testing (항상)

변경 직후 실시:

1. **콘솔 오류 확인** — 브라우저 개발자 도구에서 경고/오류 없음
2. **기본 흐름** — 다이어리 로드, 필터링, 카테고리 전환이 정상
3. **수정된 기능** — 직접 관련된 기능이 의도대로 작동
4. **인접 기능** — 수정한 부분의 상위/하위 기능 동작 확인

## Layout & Content (큰 변경 시)

UI/CSS 변경 후:

1. **긴 콘텐츠** — 길이 제약 없는 다이어리 텍스트에서 레이아웃이 깨지지 않음
2. **반응형** — 모바일(375px), 태블릿(768px), 데스크톱(1024px+) 모두 검증
3. **여백과 정렬** — 기존 시각적 일관성 유지, 새로운 스타일이 시스템에 맞음

## Regression Checklist

**상태 & 이벤트 변경 시:**
- 상태가 올바르게 업데이트됨
- 이벤트 리스너가 중복/누락되지 않음
- 이전 상태로 돌아가는 흐름이 작동

**데이터 구조 변경 시:**
- 기존 다이어리 로드 가능
- 필터링/검색 로직이 새 구조에 맞음
- Insight 분석에 필요한 메타데이터(category, label, date) 보존

**DOM/CSS 변경 시:**
- 클릭 영역 변경 시 상호작용성 유지
- 스타일 병합 시 기존 스타일 우선순위 확인
- 반응형 레이아웃 breakpoint 검증
